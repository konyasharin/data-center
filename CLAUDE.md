# CLAUDE.md — контекст проекта Data Center

## Что это

Одиночный 3D-симулятор про дата-центры, ИИ, производство и войну.
Движок — **Godot 4.7 (.NET)**. Мир реальный. Реальное время с управляемым
игроком ускорением.

Полный дизайн — в `docs/`. **Перед любой работой по геймплею читай
`docs/00-vision.md` и `docs/02-progression.md`; перед любым кодом —
`docs/10-tech-architecture.md`.**

## Стадия

Проект пустой: есть только `project.godot`, иконка и дизайн-документация.
Кода нет. Первая цель — вертикальный срез из `docs/12-roadmap.md`.

## Незыблемые правила (нарушение = переписывать проект)

1. **Данные симуляции никогда не живут внутри `Node`.** Состояние — в массивах
   (`PackedFloat32Array` / структуры массивов), визуал — производная, которую
   можно выбросить и пересоздать в любой момент. Подробно: `docs/10`.
2. **Сервер — не нода.** Стойка = меш + `MultiMesh` юнитов + текстура
   состояний для индикаторов. Никаких коллайдеров на отдельных серверах.
3. **Работник — не своя нода.** Тела берутся из пула (~60–80 штук) только для
   видимых агентов; остальные существуют как строки в массиве или как бригады.
4. **Все системы считаются аналитически, а не пошагово.** Тик может быть длиной
   в полтора игровых часа (ускорение ×100). Температура, заряд, прогресс
   обучения, заполнение складов — по формуле равновесия с интерполяцией.
5. **Отказы не симулируются, а выбираются** из распределения: сэмпл Пуассона по
   агрегату, затем материализация конкретных индексов. Стоимость O(отказов),
   не O(серверов).
6. **Сейв версионирован с первого коммита** (`SAVE_VERSION` + цепочка миграций),
   бинарный, хранит только отклонения от процедурного состояния. `docs/11`.

## Раскладка кода (предложение, менять осознанно)

```
sim/     C#  — ядро симуляции. Не знает про сцены, ноды и рендер вообще.
view/    C#/GDScript — представление: спавн визуала из данных, пулы, LOD.
ui/      GDScript — 2D-интерфейс (компьютер игрока), диегетические экраны.
game/    склейка: автолоады, менеджер времени, загрузка/сохранение.
assets/  модели, текстуры, звук.
docs/    дизайн-документация.
```

- **C#** — всё, что перебирает тысячи элементов: симуляция, задачи, экономика,
  сериализация. GDScript для этого слишком медленный.
- **GDScript** — UI, скриптуемые события, настройки, быстрое прототипирование
  правил.
- `sim/` не должен ссылаться на `Godot.Node`. Проверяемая граница: ядро обязано
  собираться и тестироваться без сцены.

## Технические заметки по текущему `project.godot`

- `renderer/rendering_method = "gl_compatibility"`. Для игры с массовым
  инстансингом, запечённым светом и окклюзией **вероятно понадобится Forward+**;
  Compatibility имеет ограничения по части возможностей рендера. Решение
  отложено — см. `docs/13-open-questions.md`, пункт «Рендерер».
- `rendering_device/driver.windows = "d3d12"` влияет только на Forward+/Mobile,
  при Compatibility игнорируется. Расхождение безвредно, но учитывать.
- Физика — Jolt. Работникам физические тела **не выдаются** (см. правило 3),
  Jolt нужен только игроку и редким объектам.

## Язык и оформление

- Общение с пользователем — **по-русски**.
- Документация и комментарии в дизайн-доках — по-русски.
- Идентификаторы в коде — английские, по конвенциям C#/GDScript.
- Коммиты — Conventional Commits, короткое описание по-английски, lowercase.
  **Без `Co-Authored-By`.**

## Чего не делать

- Не создавать ноду на каждую сущность симуляции — ни «пока для прототипа»,
  ни «потом оптимизируем». Это ровно тот путь, который убивает проект.
- Не хранить состояние в сцене, из которой его нельзя сериализовать отдельно.
- Не писать сейв в JSON.
- Не добавлять комментарии, объясняющие то, что и так видно из кода.
